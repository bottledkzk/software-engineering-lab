## 1. 文档说明

### 1.1 目的与范围

本文档是实验二交付物，把实验一的需求基线转化为**可实现、可测试、可追溯**的系统设计：架构与模块划分、关键流程、接口、数据、界面交互、非功能应对、异常处理、设计决策与权衡、追溯矩阵、测试与验证考虑、需求基线与变更说明，共 12 项设计要素。

设计对象沿用实验一选题（轻量级益智消除类网页游戏《星尘消除》），**不改换选题**；需求编号全部沿用实验一 v1.2，未重新编号（衔接要求）。

### 1.2 读者与用途

| 读者 | 用途 |
| --- | --- |
| 实现者（本人） | 按第 4~8 章实现模块、接口与界面，不擅自偏离接口约定 |
| 测试者 | 按第 12 章追溯矩阵与第 13 章测试设计，把 `AC-01~AC-37` 落成用例 |
| 评阅者 | 核对 12 项设计要素是否齐备、设计是否与需求一致、是否可实现 |

## 3. 架构设计

### 3.1 架构风格与总体视图（图 1）

采用**四层分层架构 + 纯逻辑领域层**：表现层负责渲染与输入，应用层负责状态机与流程编排，领域层是全部玩法规则的唯一实现（无 DOM 依赖），基础设施层封装浏览器能力并可被替换。

```
                    ┌──────────────────────────────┐
                    │ 表现层 ARCH-01               │
                    │ ui.js：Canvas 棋盘渲染、       │
                    │ DOM 面板、输入事件、动画队列    │
                    │ index.html / styles.css       │
                    └──────────────┬───────────────┘
                                   │ 调用（只读状态 + 发事件）
                    ┌──────────────▼───────────────┐
                    │ 应用层 ARCH-02               │
                    │ main.js：游戏状态机、页面导航、 │
                    │ 存档时机、道具与结算编排        │
                    └──────────────┬───────────────┘
                                   │ 调用（纯函数/确定性接口）
                    ┌──────────────▼───────────────┐
                    │ 领域层 ARCH-04（纯逻辑）       │
                    │ board.js 玩法引擎              │
                    │ score.js 计分与星级            │
                    │ levels.js 关卡配置与校验        │
                    │ config.js 全局常量             │
                    └──────────────┬───────────────┘
                                   │ 依赖注入（backend/rng）
                    ┌──────────────▼───────────────┐
                    │ 基础设施层 ARCH-05            │
                    │ storage.js（localStorage）     │
                    │ audio.js（Web Audio）          │
                    │ sw.js（Cache API / SW）        │
                    └──────────────────────────────┘
```

**为什么是"纯逻辑领域层"**：把玩法规则与浏览器 API 彻底隔离，可以用 Node 直接跑断言（`game/tests/logic.test.mjs` 64 项），既支撑 NFR-08 可维护性，也让第 13 章的测试设计可落地。这是本架构最关键的取舍（见 DEC-02）。

### 3.2 组件职责与依赖（表）

| 编号 | 组件 | 职责（单一职责描述） | 依赖 | 被谁依赖 | 可测试性 |
| --- | --- | --- | --- | --- | --- |
| ARCH-01 | 表现层（`ui.js` + 页面） | 棋盘与 UI 渲染、输入采集、动画播放与输入锁、响应式布局 | 应用层事件、领域层只读数据 | 用户 | 手工/界面走查 |
| ARCH-02 | 应用层（`main.js`） | 状态机（页面/局内阶段）、流程编排、存档时机、金币与解锁结算 | 领域层、基础设施层 | 表现层 | 逻辑可单测（编排为纯函数） |
| ARCH-03 | 领域层（纯逻辑） | 棋盘与消除规则、特殊方块、计分、星级、关卡配置与校验 | 无（仅 `config.js` 常量） | 应用层、测试 | **Node 直接单测** |

| ARCH-06 | 关卡配置数据（`levels.js`） | 30 关的棋盘/颜色/步数/目标/星级基准的单一数据来源 | `config.js` | 领域层、应用层 | 配置校验 + 校准脚本 |
| ARCH-07 | 测试与校准工具（`game/tests/*`） | 断言、模拟玩家、难度校准、性能烟测 | 领域层 | 开发者/评阅者 | 命令行可复跑 |
| ARCH-08 | 离线缓存层（`sw.js`） | 静态资源缓存、后台更新、版本清理 | Cache API | 浏览器 | 断网复测（AC-33/34/37） |

### 3.3 依赖方向与依赖规则（图 2）

```
   表现层 ──▶ 应用层 ──▶ 领域层 ──▶ config（常量）
      │           │
      └───────────┴──▶ 基础设施层（storage / audio）
   sw.js（独立线程，不参与上述调用链，仅与浏览器缓存交互）
```

**依赖规则（实现必须遵守）**：

1. **单向依赖**：表现层 → 应用层 → 领域层，禁止反向依赖；领域层不得出现 `document`/`window`/`localStorage` 等浏览器 API。
2. **平台耦合收敛于一处**：浏览器能力通过基础设施层封装，`storage.js` 以**后端注入**方式接收存储实现（`createStorage(backend)`），浏览器侧由 `browserStorage()` 提供 `localStorage`；测试侧注入内存 mock。这是"领域层可测"的关键，也是 ERR-01~ERR-04 能覆盖全部异常路径的前提。
3. **随机性可注入**：`board.js` 的所有随机行为通过 `rng` 参数注入（默认 `Math.random`），使测试与难度校准可复现（第 13 章 TEST-04）。
4. **无循环依赖**：模块依赖矩阵见 4.11，矩阵上三角为空，无环。
5. **状态单向流动**：局内状态由应用层持有，表现层只读渲染并发事件，不直接修改棋盘数据。

### 3.5 运行时视图（图 4）

```
浏览器主线程
 ├─ 事件循环：click/pointerdown/keydown ──▶ ui.js 输入处理（含输入锁 UI-03）
 ├─ 状态机：main.js 持有 { page, level, board, movesLeft, score, coins, items }

```

关键运行时约束：
- 动画期间**锁定输入**（UI-03），避免并发交换导致状态错乱（FR-02-3、AC-07）。
- 每次交换的结算在**单次调用内完成**（`resolveSwap` 为同步确定性函数），动画只是对已确定结果的回放，因此"动画不改变判定"（FR-16-2）。

### 3.6 关键架构决策摘要（详见第 11 章）

| 编号 | 决策 | 一句话理由 |
| --- | --- | --- |
| DEC-01 | 四层分层 + 纯逻辑领域层 | 玩法可脱离界面自动化验证，异常路径可注入测试 |
| DEC-02 | 零依赖原生 ES 模块，不用打包器/框架 | 满足 NFR-01e 包体与 NFR-02c 无插件；课程规模无需框架 |

### 3.7 架构与选题规模的匹配性

| 常被过度设计的点 | 本设计的选择 | 理由 |
| --- | --- | --- |
| 状态管理库（Redux 等） | 单个状态对象 + 显式状态机（MOD-08） | 状态维度少（页面/关卡/局内），库带来的抽象成本大于收益 |
| 打包器（Vite/webpack） | 原生 ES 模块直接上线 | 无依赖需要打包；省去构建步骤与产物体积 |
| 服务端 + 数据库 | 无后端，localStorage 存 ≤50 KB | 单机定位；服务器成本与隐私负担不可接受（范围外） |
| 微服务/插件化架构 | 9 个模块的扁平分层 | 课程规模；插件化会带来无收益的间接层 |
| WebGL 渲染 | Canvas 2D | 方块数量级 ≤81，2D 足够；WebGL 增加复杂度与兼容风险 |

### 3.8 构建与依赖管理设计

**制品（Artifact）**：交付制品是**一组静态资源**——`index.html`、`styles.css`、`js/{config,score,levels,board,storage,audio,ui,main}.js`、`sw.js`、`assets/audio/*`（懒加载）。制品即源码，无编译产物。

**为何不引入构建系统**：构建系统的价值来自处理多源文件定位、第三方库依赖、复杂依赖关系、构建顺序、多语言/多编译器协调与可重复性。本项目：①**无第三方库**；②模块 9 个、依赖单向无环（§4.11）；③**单语言**（JavaScript，浏览器直接执行 ES 模块）；④无编译产物——因此构建系统的复杂度大于收益，明确**不引入**（DEC-02）。若未来需要压缩/转译/打包，应采用**基于制品的声明式构建**（声明制品与依赖，由构建系统决定 How），避免 Shell 脚本式构建（难维护、易出错、与环境耦合）。

**依赖清单与分类**：

| 依赖类别 | 本项目情况 | 说明 |
| --- | --- | --- |
| 外部依赖（库 Libraries） | **0 个** | 无第三方库、无 CDN、无框架（NFR-01e、NFR-05a） |
| 内部依赖（组件 Components） | **9 个模块** | 见 §4.11；全部同仓自研，团队完全可控 |
| 运行时依赖 | 浏览器平台能力 | Canvas 2D、Web Audio、Web Storage、Service Worker（§6.3，均含降级路径） |
| 测试时依赖 | Node.js ≥18 | 仅 `game/tests/` 使用，**不进入交付制品** |

**依赖风险自查**（对照课程列举的四类依赖问题）：

| 风险 | 结论 | 依据 |
| --- | --- | --- |
| 菱形依赖（同一库多版本） | **不存在** | 无外部库，无版本冲突面 |
| 传递依赖 | **不存在** | 无外部库，不存在"A→B→C"链条，无需"严格传递模式" |
| 循环依赖 | **设计上消除** | §4.11 单向矩阵无环；共享常量下沉为最底层组件 `config.js`——即"提取独立组件消除循环"的**永久对策**，而非依赖"构建阶梯"式临时对策 |
| 依赖地狱 | **不存在** | 依赖图为 9 节点、最大深度 2 的简单 DAG |

**版本与兼容策略**：数据模式（存档 `version`）采用整数递增，语义对应 SemVer 的 **MAJOR**——仅不兼容结构变更才递增并触发迁移/重置（DATA-03）；兼容性新增字段不递增版本号（由 `normalizeSave()` 补齐缺省）。文档版本采用 `v主.次`（如 v1.2），变更逐条记录于实验一 §11.3 与本包《03_需求变更说明》。

**构建/交付最佳实践对齐**："构建脚本即代码" → 本项目以 `tools/md2docx.py` 生成文档制品、以 `game/tests/*.mjs` 承担质量门禁，二者均纳入版本控制且可重复执行；提交信息写明变更范围与验证结果（课程所述"非常规文档"要求）。

### 4.3 MOD-02 计分模块（`score.js`）

| 接口 | 公式 | 边界与约定 |
| --- | --- | --- |
| `comboScore(clearedCount, comboIndex)` | `clearedCount × 20 × min(1+0.5×(n−1), 2.5)` | `comboIndex ≥ 1`；`clearedCount ≥ 0` |

### 4.4 MOD-03 关卡模块（`levels.js`）

### 4.5 MOD-04 玩法引擎（`board.js`）——核心模块

**内部结构**：

| 组成 | 说明 |
| --- | --- |
| 数据表示 | `Board = { rows, cols, colors, cells: Cell[] }`，`Cell = { color: 0..colors-1, special: null\|'stripeH'\|'stripeV'\|'bomb'\|'rainbow' } \| null`；**一维数组 + 行优先索引**（DATA-02） |
| 索引工具 | `idx/rowOf/colOf/cellAt/isSpecial/isRainbow/cloneBoard` |
| 匹配算法 | `findRuns()`（横/竖 run）→ `findMatches()`（union-find 合并相交 run 成分组，按形状判定条纹/炸弹/彩虹）；`matchAt(r,c)` 为 O(1) 局部判定，用于合法性检查 |
| 合法性 | `findLegalMoves()`：对每个相邻对做"交换→`matchAt` 判定→换回"；**双特殊**与**彩虹**交换无条件合法（FR-02-4） |
| 结算 | `resolveSwap(board, a, b, rng)`：交换 → 判定有效/弹回 → 组合爆发/彩虹效果 → 连锁循环（消除→触发特殊→计分→合成特殊→下落补充）→ 死局洗牌 |
| 不定式（不变式） | ① 棋盘始终满格（无空洞）；② `cells.length === rows × cols`；③ 特殊方块必定有合法 `color`；④ 结算结束后不存在"未处理的连线"（若有则由连锁循环吸收） |
| 复杂度 | 匹配 O(n)；合法性 O(n)；单次结算 O(n·k)（k 为连锁次数，实测最长 9~11 连） |

**对外接口（详见 6.1 API 表）**：`createBoard`、`findMatches`、`findLegalMoves`、`isDeadlock`、`matchAt`、`shuffleBoard`、`resolveSwap`、`applyHammer`、`applyShuffleItem`、`cloneBoard` 等。

**内部关键设计**：
- 结算采用 `clearedEver` 集合与 `shuffleGuard` 计数，保证"同一格不会被重复计分""洗牌最多 5 次"，避免死循环（ERR-08）。
- `specialEffectCells()` 按类型给出影响格（条纹 = 整行/整列；炸弹 = 中心 3×3；彩虹 = `mostCommonColor()` 对应颜色的全部方块）；彩虹被**交换**时的分支与并列取色规则见 **§7.2 DATA-02「特殊方块合法性」行**——该行为彩虹语义的**唯一权威定义**，本节不另作表述（避免同一规则出现两个版本）。

### 4.6 MOD-05 存档模块（`storage.js`）

| 能力 | 实现要点 |
| --- | --- |
| 后端注入 | `createStorage(backend, now)`；`backend` 为 `{getItem,setItem,removeItem}` 或 `null`（内存降级） |
| 读取状态机 | `load()` 返回 `status ∈ {ok, fresh, corrupt, migrated, unavailable}` |
| 结构校验 | `isValidSave()`：版本、解锁关卡、金币、道具、星数、设置的类型检查 |
| 归一化 | `normalizeSave()`：钳制金币 ≥0、道具 0~99、昵称 ≤8 字、补默认字段（防手改存档） |
| 版本迁移 | `migrateSave()`：低版本升级；高版本无法降级 → `null` → 走损坏流程 |
| 原子写 | 先写 `stardust_save_tmp` 再覆盖 `stardust_save`，最后删除临时键 |
| 损坏备份 | 原文写入 `stardust_save_corrupt_<时间戳>` 后重置 |
| 写入失败 | 捕获返回 `{ok:false, error}`，由应用层弹出横幅（FR-11-5） |
| 浏览器入口 | `browserStorage()`：探测 localStorage 可用性（写-删探针），不可用则返回内存模式实例 |

### 4.7 MOD-06 音效模块（`audio.js`）

- **职责**：合成/播放消除、特殊触发、连锁、过关/失败、按钮音效与轻量 BGM；音量与开关独立（FR-14-1）。
- **降级**：`AudioContext` 不存在或被策略阻止时，所有接口变为空操作并置 `available=false`，界面不报错（ERR-06、AC-28）。
- **懒加载**：首次用户交互后才创建 `AudioContext` 与加载音频资源（满足 NFR-01f 与浏览器自动播放策略）。
- **资源策略**：优先合成（无需文件），BGM 单文件 ≤500 KB 且懒加载。

### 4.8 MOD-07 表现层模块（`ui.js`）

| 子职责 | 设计要点 |
| --- | --- |
| 棋盘渲染 | Canvas 2D；方块绘制包含**颜色 + 形状双编码**（FR-19）；设备像素比适配 |
| 动画队列 | 交换→消除→下落→补充→特殊触发串行播放，时长取 `ANIM` 常量；结算动画可点击跳过（FR-16） |
| 输入处理 | 点击两点交换、拖拽交换、键盘方向键+确认（FR-02、FR-18）；统一转为 `onSwap(a,b)` 事件 |
| 输入锁 | 动画播放期间 `inputLocked=true`，忽略新输入（UI-03、AC-07） |
| 面板更新 | 目标进度、剩余步数、得分、道具数量用 DOM 文本更新，避免整屏重绘 |

### 4.9 MOD-08 应用层模块（`main.js`）

- **状态机（页面维度）**：`HOME → LEVEL_SELECT → PLAYING → RESULT → LEADERBOARD → SETTINGS`，转移表见 8.1。
- **状态机（局内维度）**：`IDLE → SWAPPING → RESOLVING → SETTLING → (WIN|LOSE)`，见 5.2。
- **职责**：加载存档 → 应用降级提示 → 驱动页面 → 局内编排（交换、道具、结算）→ 按存档时机调用 MOD-05 → 维护金币/星/解锁/排行榜。
- **存档时机**：过关/失败结算、解锁变化、金币与道具变化、昵称与设置变化、`visibilitychange`/`beforeunload`（FR-11-1）。

### 4.10 MOD-09 离线缓存模块（`sw.js`）

- **策略**：`install` 预缓存关键资源（`index.html`、`styles.css`、`js/*.js`）；`fetch` 采用 cache-first + 后台更新（stale-while-revalidate 的简化版）；`activate` 清理旧版本缓存。
- **版本管理**：缓存名 `stardust-v<版本>`；版本不一致时清理旧缓存并回退在线加载（FLOW-01 异常分支）。
- **降级**：注册失败或环境不支持（`file://`、隐私模式）时不影响游戏可玩性，仅在设置页显示"离线不可用"（ERR-07、AC-34）。

### 4.12 内聚与耦合说明

- **高内聚**：每个模块围绕单一变化源组织——数值变化只影响 `config`；规则变化只影响 `board`；关卡变化只影响 `levels`；存储方式变化只影响 `storage`。
- **低耦合**：模块间只通过函数参数与返回值通信，无全局可变状态；随机性与存储后端**显式注入**，使测试可替换、行为可复现。
- **耦合点清单（唯一三处）**：① `ui`↔`main` 的事件回调；② `main`↔`storage` 的存档时机；③ `sw`↔浏览器缓存。其余模块之间为单向纯函数调用。

### 5.2 FLOW-02 一次交换的完整结算（图 6）

**触发**：玩家完成一次相邻交换（点击两点 / 拖拽 / 键盘）。

```
        ┌──────────┐  输入被锁（动画中）→ 丢弃
        │  IDLE    │
        └────┬─────┘
             │ onSwap(a,b)
        ┌────▼─────────────┐
        │ SWAPPING         │ 交换两格 → 判定：
        └────┬─────────────┘
             ├─ 无可消除连线 且 非双特殊 且 非彩虹 ──▶ 弹回动画（≤300 ms），
             │                                       步数不变 → 回到 IDLE（AC-04）
             └─ 有效（3 连 / 双特殊 / 彩虹） ──▶ 步数 -1（FR-02-4）
        ┌────▼─────────────┐
        │ RESOLVING        │ 连锁循环：消除→触发特殊→计分→合成特殊→下落补充
        └────┬─────────────┘      （每轮 comboIndex+1，倍率封顶 2.5）
             └─ 循环结束 ─▶ 若死局：自动洗牌（不扣步数，提示文案） 
        ┌────▼─────────────┐
        │ SETTLING         │ 判定目标：达成 → WIN；步数=0 未达成 → LOSE；否则回 IDLE
        └──────────────────┘
```

| 路径 | 判定条件 | 结果 | 对应 AC |
| --- | --- | --- | --- |
| 正常 | 交换形成 3 连及以上 | 消除、连锁、步数 −1、得分按 FR-06 累加 | AC-03、AC-05 |
| 分支 A | 交换涉及彩虹与任意方块 | 清除全屏该色，步数 −1 | AC-35 |
| 分支 B | 两个特殊方块相邻交换 | 十字组合爆发（3 行 3 列），按 2 次连锁计分，步数 −1 | AC-10 |
| 分支 C | 条纹/炸弹与普通方块交换但未成 3 连 | 弹回，步数不变 | AC-04 |
| 分支 D | 连锁结束后棋盘死局 | 自动洗牌（不扣步数）并提示"无可用步数，已重新洗牌" | AC-06 |
| 异常 | 动画播放中重复输入 | 输入锁丢弃，不产生第二次结算 | AC-07 |
| 异常 | 连锁中再次出现连线 | 由内部循环继续吸收（不返回给上层），直至无连线 | AC-05 |

接口与数据：`API-07 resolveSwap()`；`DATA-02` 棋盘模型；模块 MOD-04（结算）、MOD-07（动画）、MOD-08（步数与流程状态）。

### 5.3 FLOW-03 特殊方块的合成与触发链

1. **合成**（`findMatches`）：横/竖 4 连 → 条纹（按方向）；T/L 形 → 炸弹；≥5 连 → 彩虹。合成位置优先取"本次交换的两个格子之一"，否则取分组内中间格（保证玩家可预期）。
2. **触发**（结算循环内）：被包含在消除集合中的特殊方块 → 调用 `specialEffectCells()` 生成影响格 → 加入待消除队列（`queue`）→ 下一轮统一消除与计分。
3. **链式反应**：影响格中若含其他特殊方块，则继续入队；`clearedEver` 集合保证同一格不重复入队、不重复计分（ERR-08 防死循环）。
4. **异常路径**：若一轮内待消除集合为空且无新连线 → 循环终止（保证有限步收敛）。

对应需求：FR-04、AC-08/AC-09/AC-10；接口 `API-08 findMatches`、`API-07 resolveSwap`。

### 5.4 FLOW-04 棋盘初始化与死局恢复

| 场景 | 流程 | 需求/验收 |
| --- | --- | --- |
| 关卡开局 | 逐格随机取色（拒绝"会立刻形成 3 连"的颜色）→ 全盘校验（无连线 + 至少 1 个合法交换）→ 不满足则整盘重新生成，最多 50 次 | FR-01、AC-01/AC-02 |
| 兜底 | 50 次仍不满足 → 构造式洗牌修正，保证"开局可玩"（不阻塞游戏） | FR-01 异常处理 |
| 局内死局 | 结算结束时 `isDeadlock()` 为真 → `shuffleBoard()`：逐格挑选"不形成 3 连"的颜色进行重排（保留特殊方块位置）→ 校验可玩 → 不满足则重试（最多 80 次）→ 仍不满足则随机改色直至可玩 | FR-03-3、AC-06 |

> **三个循环上限的嵌套关系（实现按此编写，消除"80 次 vs 5 次"的歧义）**：三者属**嵌套**而非互斥场景——
> ① **跨轮上限 5**：一次交换结算 `resolveSwap()` 内部的连锁循环最多触发 5 次洗牌（`shuffleGuard < 5`），防止"洗牌 → 仍死局 → 再洗牌"的跨轮死循环；
> ② **单次洗牌内上限 80**：每次 `shuffleBoard()` 内部先做 ≤80 次**构造式重排**（保留颜色池、逐格避开 3 连）；
> ③ **兜底上限 500**：80 次全部失败后进入 ≤500 次**随机改色**（`while (isDeadlock(board) && guard++ < 500)`，可能残留连线，由调用方继续结算吸收）。
> 总操作上界 = 5 × (80 + 500)，共同保证有限步返回（ERR-08）。另：关卡**初始化**的重试上限为 50 次（`createBoard()`，超出后强制调用 `shuffleBoard()` 修正）。

### 5.5 FLOW-05 关卡目标判定、结算与解锁

| 阶段 | 处理 |
| --- | --- |
| 局内判定 | 每次连锁结束判定一次：`score` 型比较局内累计得分，`clear` 型比较目标色消除计数（含锤子消除的方块，但不计分） |
| 过关 | 目标达成 → 立即结算（不等步数耗尽）→ `total = 局内分 + 剩余步数 × bonusPerStep`（FR-06-5） |
| 失败 | 步数归零且未达成 → 失败结算（不计步数奖励），星级 0 且不覆盖历史记录 |
| 星级 | `starsFor(total, scoreTarget, true)`：过关**至少 1 星**，R ≥1.3→2 星，R ≥1.6→3 星 |
| 奖励与解锁 | 首次过关 +30 金币；首次 3 星额外 +20；通关后解锁下一关（章内线性，第 10 关解锁下一章） |
| 排行榜写入 | 更新该关最高分（保序保留前 10 条）与章节总星/总分榜（本机） |
| 存档写入 | 结算结束时立即保存（FR-11-1） |

对应需求：FR-05、FR-07、FR-08、FR-10；接口 `API-05 finalScore`、`API-06 starsFor`；数据 `DATA-03`。

### 5.6 FLOW-06 道具使用

| 道具 | 触发 | 处理 | 异常/边界 |
| --- | --- | --- | --- |
| 洗牌（100 金币） | 局内点击道具 → 二次确认 → 扣币 → `applyShuffleItem()` | 重排棋盘（不消耗步数），失败局面自动校验可玩 | 金币不足 → 按钮置灰（不出错）；持有数 0 → 禁用 |
| 锤子（150 金币） | 点击道具 → 进入"选格"模式 → 点击目标格 | 消除该格、下落补充；**计入消除目标数量但不计分、不触发特殊效果**（FR-09） | 点击空格/非法位置 → 忽略；取消选择 → 退出选格模式 |
| +5 步（200 金币） | 局内或失败结算界面点击 | 剩余步数 +5，棋盘与得分保留 | 仅在"未过关且局内未结束"或"失败结算界面"可用 |

道具消耗规则：**使用即消耗**，随后刷新/退出本局不返还（FR-09-2，界面需在确认弹窗中告知）。持有上限 99。

> **选格模式与输入锁的状态交互（UI-03 / API-35 / API-43，实现按此编写）**：
> ① 点击"锤子"→ 二次确认 → 扣币 → 调 `game.onItemModeChange('enter')`（API-43）。道具**只能在 `IDLE` 阶段点击**；结算动画期间的点击按 FLOW-02 异常路径丢弃，因此进入选格模式时动画输入锁必然处于**释放**状态。
> ② 选格模式期间 `inputLocked = false`（可点格子），但**棋盘交换被禁用**：`game.onSwap()` 收到的调用一律忽略，避免"选格时误交换"。
> ③ 点中目标格 → `applyHammer()`（API-09）→ 播放消除与下落动画并**重新上锁**（`ui.setInputLocked(true)`，API-35）→ 动画播放完毕解锁。
> ④ 点"取消"或点棋盘空白 → `game.onItemModeChange('cancel')`（API-43），从未消耗状态回到普通输入。
> ⑤ 选格模式下切后台（API-44）→ **先退出选格模式再存档**，避免恢复时停留在半完成状态。

### 5.9 FLOW-09 首次进入关卡的新手引导（图 8）

**触发**：首次进入 1-1 关（存档 `guided=false`）。**关键时序约定**：Service Worker 的注册是**异步且不阻塞**的，引导与游戏流程**不等待**缓存完成；存档读取必须先于引导判定。

```
① 解析 HTML 与 ES 模块
   └─ DOMContentLoaded → navigator.serviceWorker.register('sw.js')  ← 异步，不 await，不阻塞
② storage.load()  ──▶ 按 status 分支（FLOW-07：ok/fresh/corrupt/migrated/unavailable）
③ 渲染主菜单（此时 SW 可能仍在 install/预缓存，界面不等待）
④ 进入 1-1 关：读 guided=false → 创建棋盘（FLOW-04）
⑤ 引导遮罩第 1 步：高亮一对可交换方块（"拖动或点击交换相邻方块"）
⑥ 玩家完成一次有效交换 → FLOW-02 结算 → 引导第 2 步（解释计分与连锁倍率）
⑦ 引导第 3 步：指向目标进度条与剩余步数 → 点击"我知道了"或达成触发条件
⑧ 写 guided=true（存档时机：设置变化）→ 本机不再显示引导（FR-13-2）
⑨ 首次合成某类特殊方块 → 气泡提示其效果（每类一次，标志位存 DATA-03.tipsSeen）
```

| 路径 | 处理 | 参与模块/接口 | 数据 |
| --- | --- | --- | --- |
| 正常 | 三步引导 → 写完标志位 → 正常游戏 | MOD-07 `showGuide()`、MOD-08 | 读写 `guided`、`tipsSeen` |
| 分支（跳过） | 任一步点"跳过" → 立即关闭遮罩，仍写 `guided=true`（不重复打扰，FR-13-2 允许） | API-37、API-19 | 写 `guided` |
| 分支（非首次） | `guided=true` → 直接进入游戏，不创建遮罩 | MOD-08 | 只读 |
| 异常（存档不可用） | `status=unavailable` → 引导仍显示，标志位仅存内存（本次会话有效） | ERR-04 | 内存态 |
| 异常（引导期间切后台） | 下次进入该关时若 `guided` 未写成功 → 重新引导（幂等，不产生副作用） | ERR-10 | — |

对应需求：FR-13、AC-26、NFR-03b；接口 API-37（引导遮罩）、API-33（渲染）、API-19（存档写入）。

### 6.3 浏览器平台接口（外部依赖，均为平台能力而非第三方服务）

| 平台能力 | 用途 | 可用性检测 | 不可用时的降级 |
| --- | --- | --- | --- |
| Canvas 2D (`getContext('2d')`) | 棋盘与动画渲染 | 返回 `null` 检测 | 无法降级（属 NFR-02a 范围内必支持项） |
| Web Audio API (`AudioContext`) | 音效与 BGM | `typeof AudioContext !== 'undefined'` 且创建成功 | 静默降级，`available=false`（ERR-06、AC-28） |
| Web Storage (`localStorage`) | 存档 | 写-删探针 | 内存模式，提示"进度仅本次有效"（ERR-04、AC-24） |
| Service Worker + Cache API | 离线缓存 | `'serviceWorker' in navigator` 且注册成功 | 在线模式 + 设置页提示（ERR-07、AC-34） |
| `requestAnimationFrame` | 动画帧调度 | 存在性检测 | 回退 `setTimeout(16ms)`（兼容保留，正常浏览器不触发） |
| `visibilitychange` / `beforeunload` | 切后台/关闭前存档 | 事件绑定 | 无（可选增强，缺失仅影响"离开前保存"的及时性） |

### 6.4 外部系统/第三方接口

**本系统不依赖任何外部系统或第三方服务**：无服务端接口、无数据库、无 CDN、无第三方 SDK、无统计埋点（NFR-05a：除加载自身静态资源外无任何网络请求）。因此不存在"第三方接口的输入/输出格式与配额限制"，也不需要 API Key 或鉴权；离线可玩即为该结论的验收方式（AC-33）。

### 7.1 DATA-01 关卡配置模型（持久于代码中的配置表，不写入用户存储）

### 7.2 DATA-02 运行时棋盘模型（内存态，不持久化）

```ts
Board = { rows: int, cols: int, colors: int, cells: Cell[] }   // cells 长度 = rows × cols，行优先一维索引
Cell  = null | { color: int(0..colors-1), special: null | 'stripeH' | 'stripeV' | 'bomb' | 'rainbow' }
索引   index(r,c) = r * cols + c      r = floor(index / cols)      c = index % cols
```

| 约束/不变式 | 说明 |
| --- | --- |
| 满格性 | 结算与动画结束后 `cells` 中不存在 `null`（下落补充保证） |
| 消除期例外 | 结算循环内部允许临时 `null`（表示刚被消除），但必须在 `gravityAndRefill()` 后恢复满格 |
| 特殊方块合法性 | `special ≠ null` 时 `color` 必须为合法颜色值。**彩虹 `color` 语义（本行为唯一权威定义，实现按此编写）**：`color` 是彩虹自身的**显示色**，不决定消除目标色。① 彩虹**被交换**时：清除「对方方块颜色」的全部方块；若对方亦为特殊方块，则改为以彩虹为中心的组合爆发（3 行 3 列）；② 彩虹**被包含在消除集合中**（被连锁或特殊效果波及）时：清除「棋盘当前数量最多的颜色」，**并列时取 `color` 索引较小者**（`mostCommonColor()` 仅严格大于才更新最优）。两种情形的目标色均由**消除时刻的棋盘状态**决定，与彩虹自身 `color` 无关——实验一 FR-04-2 所称"清除全屏该色"即指上述目标色。 |
| 不可变语义 | 棋盘由应用层持有；`ui` 只读；跨调用需要副本时使用 `cloneBoard()`（模拟与预览） |
| 生命周期 | 关卡开始时创建；结算后丢弃（**不写入存档**，符合 FR-11-2"局内状态不持久化"） |

| `version` | int | 当前 1 | 不等于当前值 → 迁移；无法迁移 → 损坏流程。**语义对应 SemVer 的 MAJOR**：仅不兼容结构变更才递增；兼容性新增字段不递增（由 `normalizeSave()` 补缺省），详见 §3.8 |
| `nickname` | string | 1~8 字符，默认"玩家"+4 位数字 | `normalizeSave()` 截断 |
| `unlockedLevelId` | string | 必须为 `LEVELS` 中的合法 id | 非法 → 回退 `1-1` |
| `coins` | int | ≥0 整数 | 负数/小数被钳制 |
| `items.shuffle/hammer/steps` | int | 0..99 整数 | 越界钳制 |
| `stars[levelId]` | int | 0..3；仅记录已通关关卡 | 与 `unlockedLevelId` 保持"已解锁的关卡星数可能为 0" |
| `bestScores[levelId]` | int | ≥0 | 与 `stars` 同源（同一局结算写入） |
| `leaderboard.total[]` | 数组 | 按 `stars` 降序、同星按 `score` 降序，保留前 10 条 | 昵称变更时同步更新显示名 |
| `leaderboard.levels[levelId][]` | 数组 | 该关前 10 条，按分数降序 | 入榜条件：高于历史第 10 名 |
| `settings.*On/Vol` | bool/int | 音量 0..100 | 音量为 0 等价于关闭 |
| `guided` | bool | 是否已看过新手引导 | FR-13-2 只显示一次 |
| `tipsSeen` | object | 四类特殊方块（`stripeH`/`stripeV`/`bomb`/`rainbow`）是否已提示过 | FR-13-3：每类首次合成提示一次，之后不再提示 |
| `updatedAt` | int | 毫秒时间戳（本机时区） | 写入时自动刷新 |

**归一化规则表（`normalizeSave()` 可直接按表实现：字段 → 缺省值 → 缺失/非法时的行为）**

| 字段 | 缺省值 | 字段缺失时 | 值非法/越界时 |
| --- | --- | --- | --- |
| `version` | `1` | 视为 `1`（按旧档处理） | 非整数 → 损坏流程（ERR-01）；高于当前版本且不可迁移 → 损坏流程（ERR-03） |
| `nickname` | `"玩家"` + 4 位随机数字 | 生成默认昵称 | 非字符串 → 默认昵称；去首尾空白后为空 → 默认昵称；长度 >8 → 截断为 8 |
| `unlockedLevelId` | `"1-1"` | `"1-1"` | 不在 `LEVELS` 的 id 集合中 → 回退 `"1-1"` |
| `coins` | `0` | `0` | 非有限数 → `0`；负数 → `0`；小数 → 向下取整 |
| `items.shuffle` / `items.hammer` / `items.steps` | 各 `1` | 各自补 `1` | 非有限数 → `1`；<0 → `0`；>99（`ITEM_CAP`）→ `99`；小数 → 向下取整 |
| `stars["<levelId>"]` | `{}` | `{}` | 键不在 `LEVELS` → 丢弃该键；值非 0~3 整数 → 丢弃该键 |
| `bestScores["<levelId>"]` | `{}` | `{}` | 键不合法 → 丢弃；值非有限数或为负 → 丢弃该键 |
| `leaderboard.total[]` | `[]` | `[]` | 非数组 → `[]`；条目缺 `nickname`/`stars`/`score` → 丢弃该条目；超过 10 条 → 按排序规则截断 |
| `leaderboard.levels` | `{}` | `{}` | 非法 levelId 键 → 丢弃；单关超过 10 条 → 截断 |
| `settings.musicOn` / `settings.sfxOn` | `true` | `true` | 非布尔 → `true` |
| `settings.musicVol` / `settings.sfxVol` | `80` | `80` | 非有限数 → `80`；<0 → `0`；>100 → `100`；小数 → 四舍五入 |
| `guided` | `false` | `false` | 非布尔 → `false` |
| `tipsSeen` | 四项均为 `false` | 四项补 `false` | 单项非布尔 → 该项 `false`；未知键 → 忽略（不写入） |
| `updatedAt` | 本次载入时刻 | 本次载入时刻（毫秒时间戳） | 非有限数 → 本次载入时刻 |

> 规则边界：归一化**只做钳制与补缺省，不猜测用户意图**；凡属**结构性**错误（JSON 解析失败、顶层非对象、版本不可迁移）一律走损坏流程（ERR-01/ERR-03），不做逐字段挽救（DEC-11）。

**示例数值可复算**（与实验一 §7.2 同步）：通关 1-1~1-5、其中 1-1/1-2 首过 3 星 → 金币 = 5×30 + 2×20 − 洗牌 100 = **90**；总星 = 3+3+2+1+2 = **11**；总分 = 各关最好分之和 = **67800**；通关 1-5 后解锁 `1-6`。

**体积预算**：30 关 × （星数 + 最好分）+ 两榜（约 10+30×10 条）→ 实测估算 ≤50 KB，远低于实测配额下限 3 MB（实验一 V-10）。

**一致性与写入策略**：

| 策略 | 设计 |
| --- | --- |
| 原子写 | 写 `stardust_save_tmp` → 覆盖 `stardust_save` → 删临时键；任一失败返回 `{ok:false}` |
| 结构校验 | `isValidSave()` 类型检查（版本/解锁/金币/道具/星数/设置） |
| 归一化 | `normalizeSave()` 钳制范围、补齐缺省字段（防手改存档导致运行期异常） |
| 损坏恢复 | 原文备份至 `stardust_save_corrupt_<ts>` → 重置默认档 → 界面提示 |
| 版本迁移 | `migrateSave()`：低版本升级；高版本（来自未来版本）→ `null` → 损坏流程 |
| 多标签页 | last-write-wins，不做实时同步（范围外），不弹冲突提示 |
| 写入时机 | 结算、解锁、金币/道具变化、设置/昵称变化、`visibilitychange`、`beforeunload`（FR-11-1） |

### 7.4 DATA-04 排行榜记录模型

| 实体 | 字段 | 约束 |
| --- | --- | --- |
| 总星榜条目 | `{ nickname, stars, score, ts }` | `stars` 为全章节总星数（0..90），`score` 为全章节总分（各关最好分之和） |
| 单关榜条目 | `{ nickname, score, ts }` | 每关保留前 10 条；`score` 为该关结算总分 |
| 排序 | 总星榜：`stars` 降序 → `score` 降序；单关榜：`score` 降序 | 相同分数按 `ts` 升序（先达者在前） |
| 防作弊 | 无（单机信任模型，FR-10-4 显式声明） | 数据仅存本机 |

### 7.5 DATA-05 数据字典（界面字段 ↔ 数据字段 ↔ 接口字段）

| 界面字段 | 数据来源 | 接口 | 类型/格式 |
| --- | --- | --- | --- |
| 剩余步数 | 应用层局内状态 | API-22 副作用 | 整数，显示 `剩余 N 步` |
| 目标进度 | `resolveSwap().clearedByColor` 或局内得分 | API-07 | `score` 型：分数；`clear` 型：`已消除 x/y` |
| 局内得分 | `resolveSwap().score` 累加 | API-07/API-12 | 整数，千分位可选 |
| 结算总分 | `finalScore()` | API-13 | 整数 |
| 星级 | `starsFor()` | API-14 | 1~3 星（图标）+ 数字 |
| 金币 / 道具数量 | 存档 `coins` / `items` | API-19/API-23 | 整数 |
| 昵称 | 存档 `nickname` | API-26 | 1~8 字符 |
| 排行条目 | 存档 `leaderboard` | API-18 | 名次/昵称/分数/星数 |

### 7.6 DATA-06 数据生命周期与留存

| 数据 | 生命周期 | 清除方式 |
| --- | --- | --- |
| 关卡配置 | 随代码发布，长期有效 | 版本更新 |
| 运行时棋盘 | 单关卡内（内存） | 结算/退出即丢弃 |
| 存档 | 跨会话持久（localStorage） | 设置页"重置进度"（清档 + 两榜，保留昵称与设置）或浏览器清除数据 |
| 排行榜 | 跨会话持久（存档内） | 同上 |
| SW 缓存 | 跨会话（Cache Storage） | 版本更新自动清理旧版本；浏览器清除数据 |

### 8.4 UI-04 动画与性能降级档位

| 档位 | 触发条件 | 表现 |
| --- | --- | --- |
| 标准 | 默认 | 完整粒子与缩放动画（时长取 `ANIM`） |
| 精简 | 检测到连续帧耗时 >25 ms（滚动窗口） | 粒子数量减半、动画时长 ×0.7 |
| 极简 | 连续帧耗时 >40 ms 或系统"减少动态效果"偏好 | 仅保留位移动画，取消粒子与缩放 |

> 动画时长上限仍满足 FR-16 的约束（精简档更短）；降级不改变任何判定结果（FR-16-2）。

### 8.5 UI-05 新手引导（FR-13）

首次进入 1-1 关时以遮罩层分 3 步引导：① 高亮一对可交换方块并提示"交换相邻方块"；② 完成一次消除后解释计分与连锁；③ 指向目标进度条与剩余步数。总时长 ≤60 s、可随时跳过、仅显示一次（`guided=true`）。特殊方块首次合成时以气泡提示其效果（每种一次）。

### 8.6 UI-06 排行榜界面（低打扰，FR-10-6）

排行榜**只在玩家主动进入时展示**：局内不显示名次、不弹排名提示、不在结算界面强推；总星榜与单关榜分页切换；条目显示名次、昵称、分数/星数、达成时间（本地时区格式）。

## 10. 异常与故障处理设计

| 编号 | 故障模式 | 触发条件 | 检测方式 | 处理路径 | 恢复策略 | 用户可见行为 | 需求/验收 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| ERR-01 | 存档损坏（非法 JSON / 结构不符） | 手改数据、写入中断、浏览器异常 | `JSON.parse` 失败或 `isValidSave()` 为假 | 备份原文至 `stardust_save_corrupt_<ts>` → 重置默认档 | 用默认档继续，旧数据可人工找回 | 主界面提示"存档损坏，已重置" | FR-11-3、AC-22 |
| ERR-02 | 存档写入失败（配额耗尽等） | 配额满、浏览器限制 | `setItem` 抛异常（捕获返回 `{ok:false}`） | 横幅提示；游戏继续，内存态保留 | 用户清理空间后下次写入即恢复 | 常驻横幅"进度无法保存，本局结果可能丢失" | FR-11-5、AC-23 |
| ERR-03 | 存档版本不可迁移 | 存档 `version` 高于当前（降级使用） | `migrateSave()` 返回 `null` | 同 ERR-01（备份 + 重置） | 默认档 | 提示"存档损坏，已重置" | FR-11-4 |
| ERR-04 | 存储不可用（隐私模式/被禁用） | 探针写入失败 | `browserStorage()` 探针异常 | 切换为内存模式实例 | 单次会话内可完整游玩 | 提示"进度仅本次有效" | FR-11-6、AC-24 |
| ERR-05 | 画布不可用 | 极端环境 `getContext('2d')` 返回 `null` | 启动检测 | 显示不支持提示页，给出兼容浏览器清单 | 用户换浏览器 | 提示页（不白屏） | NFR-02a |
| ERR-06 | 音频不可用/被阻止 | `AudioContext` 不存在或创建失败 | 创建时 try/catch | 全部音频接口降级为空操作，`available=false` | 后续交互重试创建 | 无声音但正常游玩；设置页标注"当前设备不支持音效" | FR-15-2、AC-28 |
| ERR-07 | 离线缓存不可用 | `file://`、隐私模式、注册失败 | `'serviceWorker' in navigator` 与注册结果 | 进入在线模式；不阻断游戏 | 联网即可玩；下次在 https 环境自动重试 | 设置页标注"离线不可用，请保持联网"；离线且未缓存时显示重试页 | FR-20-3、AC-34 |

| ERR-09 | 关卡配置非法 | 配置手误（步数越界、targetColor 越界等） | `validateLevel()` 返回非空错误列表 | 该关标记"配置错误"并在选关页禁用；其余关卡正常 | 修正配置后重启即恢复 | 选关页该关显示为不可用（不白屏） | FR-05 异常处理、7.1 |
| ERR-10 | 局内被中断（切后台/被杀进程） | 移动端内存回收、来电 | `visibilitychange` 触发保存；返回时检测页面是否被重建 | ≤5 min 且页面未重建 → 内存态直接继续；被重建 → 该关重置为初始状态 | 关卡进度与金币已存档，不丢失 | 重新进入该关（进度条显示该关起始状态） | FR-11-2、NFR-04b |

| ERR-12 | 无效输入（连点/拖拽越界/点空格） | 玩家快速操作 | 输入锁 + 目标格校验 | 丢弃该输入 | — | 无响应（不产生错误状态） | FR-02-3、AC-07 |

**故障处理设计原则**：① 任何平台能力缺失都不得导致白屏或崩溃，必须有"可玩但不完美"的降级路径；② 数据类故障必须"先备份、再重置、并告知"；③ 循环类风险必须有上限计数器，宁可接受次优结果也不可卡死；④ 所有用户可见提示均使用非技术语言（不出现异常堆栈或英文错误码）。

## 11. 设计决策与权衡

| 编号 | 决策点 | 备选方案 | 选择与理由 | 被否决方案及理由 |
| --- | --- | --- | --- | --- |
| DEC-01 | 总体架构 | ① 四层 + 纯逻辑领域层；② 逻辑与 DOM 混合的单文件写法；③ MVC/MVVM 框架式分层 | **①**：玩法可脱离浏览器测试（64 项断言的前提），异常路径可注入 mock，耦合点仅 3 处 | ② 不可自动测试、后期改动风险高；③ 单人课程项目引入框架抽象成本大于收益（与 G-6 冲突） |
| DEC-02 | 工程形态与构建 | ① 零依赖原生 ES 模块、无构建系统；② Vite/webpack 打包；③ React/Vue 等框架 | **①**：制品即源码、无编译步骤；构建系统的价值来源（多源文件定位、第三方依赖、构建顺序、多语言协调）在本项目**全部不成立**（详见 §3.8）；满足 NFR-01e 体积与 NFR-02c 无插件，且评阅方可直接打开源码 | ② 无依赖可打包，只增加构建复杂度与"产物—源码不一致"风险；③ 框架体积与学习成本不成比例（仅 9 个模块、DOM 更新量小）。若未来需要压缩/转译，应改用**声明式（基于制品）**构建而非 Shell 脚本式构建 |
| DEC-03 | 棋盘渲染 | ① Canvas 2D；② DOM + CSS 动画；③ WebGL | **①**：消除/下落/粒子动画在 Canvas 上性能可控，脏矩形重绘足够；实现复杂度适中 | ② 大量元素 CSS 动画在低端机上掉帧，且状态同步复杂；③ 方块 ≤81 个，WebGL 属过度设计 |
| DEC-04 | 关卡组织 | ① 配置驱动（`levels.js` 数据表）；② 每关一个类/函数硬编码 | **①**：落实 NFR-08（新增关卡不改代码），并可用脚本批量校准数值 | ② 30 关会产生大量重复代码，数值调整需改代码 |
| DEC-05 | 死局洗牌算法 | ① 构造式逐格填色；② 随机重排 + 拒绝采样；③ 直接重生成棋盘 | **①**：在 3 色棋盘下，随机重排几乎必然产生连线（实测拒绝采样 200 次仍失败）；构造式可保证"无连线 + 可玩" | ② 低颜色数下成功率极低（实现阶段已踩坑）；③ 会丢失当前特殊方块与颜色分布，破坏玩家预期 |
| DEC-06 | 离线能力 | ① Service Worker + Cache API；② 仅依赖浏览器 HTTP 缓存；③ 不做离线（需求裁剪） | **①**：可控预缓存与版本清理，落实 FR-20 与 SC-3；同时按 DA-3 降级保证 `file://` 可玩 | ② 浏览器缓存不可控，无法保证"断网刷新仍可玩"；③ 与 §2.3 目标 1 直接冲突 |
| DEC-07 | 合法性判定 | ① 局部 `matchAt()`（O(1)）；② 每次候选交换都做全盘 `findMatches()` | **①**：合法性检查在选关预览/死局判定中被高频调用，局部判定把复杂度从 O(n²) 降到 O(n) | ② 实现简单但在 30 关 × 模拟校准中造成数量级性能问题（实测已优化） |
| DEC-08 | 分组匹配 | ① union-find 合并相交连线；② 只按单条连线判定 | **①**：支持 L/T 形（炸弹方块）与"同色多线交叉"的合并判定，形状规则可精确表达 | ② 无法识别 T/L 形，会漏判炸弹方块 |
| DEC-09 | 步数奖励与星级 | ① 步数奖励与目标分挂钩（`0.8×T/M`）；② 固定 200 分/步；③ 星级直接按剩余步数比例 | **①**：保持"R=总分/目标分"的单一比值口径（FR-07-1），同时使 1/2/3 星在实测中均可达成（贪心通关局 3 星占 18%） | ② 在"达成即结算"规则下 3 星数学上不可达（已由模拟实测证伪）；③ 会与 FR-07 的比值定义冲突，需改需求 |
| DEC-10 | 存储介质 | ① localStorage 单键 JSON；② IndexedDB；③ 多键拆分 | **①**：体积 ≤50 KB，单键便于原子写与版本迁移；同步 API 在存档时机点调用无性能问题 | ② 异步 API 增加复杂度与竞态风险，收益为零；③ 多键难保证一致性 |
| DEC-11 | 存档损坏处理 | ① 备份后重置；② 直接重置；③ 尝试逐字段修复 | **①**：可追溯（保留原始数据），用户损失最小 | ② 无法排查原因；③ 修复逻辑本身易出错，且无法保证结构自洽 |
| DEC-12 | 排行榜形态 | ① 本地排行榜（本机）；② 在线排行榜 + 账号 | **①**：与"纯单机、无后端"定位一致（范围外决策）；显式声明信任模型（无防作弊） | ② 需服务器与账号，成本、隐私与范围均不允许 |
| DEC-13 | 音效实现 | ① Web Audio 合成短音效 + 懒加载 BGM；② 预置音频文件集 | **①**：合成音效零文件成本（利于 NFR-01e），并可随连锁数动态变调 | ② 多文件增加体积与首屏请求数；变调需多套素材 |
| DEC-14 | 输入模型 | ① 三种输入统一转 `onSwap(a,b)`；② 每种输入各写一套处理逻辑 | **①**：行为一致（键盘/鼠标/触屏同规则），且输入锁只需一处实现 | ② 易出现"某输入方式绕过输入锁"的不一致缺陷 |
| DEC-15 | 局内状态持久化 | ① 不持久化（刷新回该关初始状态）；② 序列化整个棋盘到存档 | **①**：单局 ≤10 分钟，收益低而序列化/恢复逻辑易出错；代价在界面显式告知 | ② 复杂度高，且与"存档 ≤50 KB"与"损坏恢复简单"目标冲突 |
| DEC-16 | 判定与动画的关系 | ① 先结算（确定性）后动画回放；② 动画回调中逐步改状态 | **①**：判定结果与帧率无关（低端机丢帧不改结果），也让"动画不改判定"可验证（FR-16-2） | ② 掉帧会改变判定时序，难以测试与复现 |
