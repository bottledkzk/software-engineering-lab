# 《星尘消除》实现说明（game/）

对应实验一《01_需求分析文档》与实验二《01_设计文档》的实现阶段。**纯 HTML5 + 原生 ES 模块，零依赖、零构建**（满足 NFR-01e 资源轻量、NFR-02c 无插件依赖）。

## 目录结构

```
game/

├── sw.js                 # 离线缓存：预缓存 + cache-first 后台更新 + 版本清理（FR-20、API-38~41）
```

## 运行方式

- **跑全部测试**（Node ≥ 18，零依赖）：
  ```
  cd game
  node tests/logic.test.mjs            # 64 项
  node tests/settlement.test.mjs       # 46 项
  node tests/api-conformance.test.mjs  # 51 条接口一致性
  node tests/wiring.test.mjs           # 9 项接线校验
  node tests/calibrate-levels.mjs      # 难度校准（可复现）
  ```
- **玩游戏（必须用本地 HTTP 服务，不能双击打开）**：
  ```
  cd game
  python -m http.server 8000        # 或 npx serve .
  # 浏览器打开 http://localhost:8000
  ```
  > ⚠️ **不能直接双击 `index.html`**：页面使用原生 ES 模块（`<script type="module">`），`file://` 协议下会被浏览器的 CORS 策略拒绝加载。这是实现阶段发现的**设计假设偏差**（《01_设计文档》DA-3/§3.4 原写"file:// 可直接可玩"，实际不成立），已在 v1.5 中修正。

## 核心实现要点（与需求文档的对应）

| 需求 | 实现位置与要点 |
| --- | --- |
| FR-01 初始化 | `createBoard`：拒绝采样保证**无初始 3 连**；再校验**至少 1 个合法交换**，50 次内未满足则洗牌修正 |
| FR-02 交换判定 | `resolveSwap`：无效交换弹回且**逐格状态完全还原**（AC-04 已验证 1641 次无效交换）；有效交换（含彩虹/双特殊）**恰好扣 1 步** |
| FR-03 连锁与死局 | 消除→下落→补充循环；「无连线且无待处理效果」时检测死局并**自动洗牌（不消耗步数）** |
| FR-04 特殊方块 | 4 连→条纹、L/T→炸弹、5 连→彩虹；双特殊交换→十字组合爆发（3 行 3 列，按 2 次连锁计分） |
| FR-05 目标与步数 | 两类目标（`score` / `clear`），达成即结算；锤子消除计入消除目标但不计分 |
| FR-06 计分 | 逐次连锁计分 = 消除数 × 20 × min(1+0.5(n-1), 2.5)；测试可逐项复算 |
| FR-07 星级 | R = 结算总分 / scoreTarget；**过关至少 1 星**，≥1.3/1.6 → 2/3 星 |
| FR-08 解锁 | `nextLevelId`：章内推进，章末进入下一章；最后一关无后继（3 章 × 10 关） |
| FR-09 金币与道具 | 洗牌 100 / 锤子 150 / +5 步 200；**使用即消耗**；失败结算界面可用 +5 步续玩（保留棋盘与得分） |
| FR-10 排行榜 | 单键存档内两榜：总星榜（按总星数、总分排序）与单关榜（按分数），按昵称 upsert，各保留前 10 |
| FR-11 存档 | 单键 `stardust_save`，写临时键后覆盖（原子性）；损坏→备份到 `stardust_save_corrupt_<ts>` 并重置；配额耗尽→横幅提示；存储不可用→内存降级并在设置页标注 |
| FR-12 界面与导航 | 6 个页面（主菜单/选关/游戏/结算/排行榜/设置）+ 顶栏返回；引导遮罩与二次确认弹窗 |
| FR-13 新手引导 | 首次进入 1-1 时三步引导（可跳过）；特殊方块首次合成提示；完成/跳过后写 `guided=true` |
| FR-14 设置与重置 | 昵称（≤8 字）、音乐/音效开关与音量、离线与音效支持状态、关于；重置保留昵称与音量 |
| FR-15 音效 | Web Audio 合成（零音频文件）；首次用户交互后创建 `AudioContext`；不可用则全部接口空操作并标注 |
| FR-16 动画 | 交换 220ms / 弹回 260ms / 消除 220ms / 下落 280ms / 特殊 380ms（`config.ANIM`）；**动画只回放已确定结果，不参与判定** |
| FR-19 色觉双编码 | 6 色 × 6 形状（圆/方/三角/菱形/五边形/六边形），灰度下仍可区分 |
| FR-20 离线缓存 | `sw.js` 预缓存 11 项关键资源；cache-first + 后台更新；版本变更清理旧缓存；不支持时降级为在线 |

## 关卡难度校准（AC-11 证据）

`tests/calibrate-levels.mjs` 用**模拟玩家**实测校准每关的星级基准分：

- 1 星线由**不动点迭代**求得：反复令 `scoreTarget ← quantile_q(以当前 scoreTarget 为停止条件的结算总分)`；收敛后 q 即模拟玩家的失败率。三章分别取 q = 10% / 20% / 30%（逐章变难）。
- 消除型关卡使用"目标色优先"策略建模，目标值 `objectiveTarget` = 目标色消除量的 P20。
- 步数奖励 `bonusPerStep = 0.8 × scoreTarget / moves`，使 **2 星 ≈ 剩余 37% 步数、3 星 ≈ 剩余 75% 步数**。

最近一次校准与验证结果（种子固定，可复现；原始输出见 `tests/last-run-calibration.txt`）：

| 指标 | 结果 |
| --- | --- |
| 贪心玩家通关率 | **83.0%**（630 局；30 关每关至少通关 1 次） |
| 休闲玩家通关率 | **44.9%**（630 局） |
| 贪心玩家星级分布 | 通关局中 1 星 41% / 2 星 41% / 3 星 18% |
| 验收分组（9 局/关，270 局） | 贪心通关率 83.0%，通关局中 3 星占 17% |

## 实现阶段发现并修订的问题

| # | 问题 | 处置 |
| --- | --- | --- |
| 1 | 固定"剩余步数 200 分/步"与星级阈值不匹配（3 星不可达） | 改为与目标分挂钩（`BONUS_RATIO = 0.8`），回写《01》FR-06-4/FR-07（M-14） |
| 2 | 消除型关卡 `targetColor` 为负（JS 负数取模） | `levels.js` 归一化 + `validateLevel` 非负校验 + 回归用例（M-14） |
| 3 | 3 色棋盘洗牌后残留连线 | 改为构造式排布，并把死局处理移入连锁循环（M-14） |
| 4 | **`file://` 下 ES 模块被 CORS 拒绝**（设计假设 DA-3 不成立） | 运行方式改为本地 HTTP 服务；《01_设计文档》v1.5 修正 DA-3/§3.4 与 ERR-07 表述 |
| 5 | 锤子"取消是否消耗"未明确 | 实现为：进入选格模式**不扣费**，选中格子才扣费与消耗；取消无代价（v1.5 写入 FLOW-06 说明） |
